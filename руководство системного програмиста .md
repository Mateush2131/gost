## 1. Общие сведения о программе

1.1. Назначение: веб-приложение портфолио с формой заявок и админ-панелью.

1.2. Функции:
- отображение портфолио;
- приём и сохранение заявок в PostgreSQL;
- защищённый доступ к админ-панели (Basic Auth);
- работа через Next.js App Router.

1.3. Технические и программные средства:
- Node.js 18+
- npm
- PostgreSQL / Supabase
- Prisma ORM
- Next.js 14, React 18, TypeScript, Tailwind CSS


## 3. Настройка программы

### 3.1. Подготовка окружения

1. Установить Node.js 18+.  
2. Клонировать / распаковать проект.  
3. Скопировать `.env.example` в `.env` и заполнить:
   ```
   DATABASE_URL=postgresql://...
   ADMIN_USER=admin
   ADMIN_PASS=ваш_пароль
   NEXT_PUBLIC_SUPABASE_URL=...
   NEXT_PUBLIC_SUPABASE_ANON_KEY=...
   ```

### 3.2. Установка зависимостей и БД

```bash
npm install
npx prisma generate
npx prisma db push
# или npx prisma migrate dev
```

### 3.3. Настройка на состав технических средств

- Для локальной разработки достаточно `npm run dev`.  
- Для production: `npm run build && npm run start` или деплой на Vercel/Railway с указанием тех же переменных окружения.  
- При смене СУБД — изменить `provider` в `schema.prisma` и `DATABASE_URL`.

### 3.4. Выбор функций

Все основные функции включены по умолчанию.  
Админ-панель можно отключить, удалив/закомментировав middleware и папку `app/admin`.

## 4. Проверка программы

### 4.1. Контрольные примеры

| Проверка | Действие | Ожидаемый результат |
|----------|----------|---------------------|
| Главная страница | Открыть `/` | Портфолио отображается |
| Форма заявки | Заполнить и отправить | Запись появляется в таблице Order |
| Админ без пароля | Открыть `/admin` | 401 Unauthorized |
| Админ с паролем | Ввести правильные данные | Панель открывается |
| Сборка | `npm run build` | Успешная сборка без ошибок |

### 4.2. Методы прогона

1. `npm run dev` → ручная проверка в браузере.  
2. `npm run build` → проверка production-сборки.  
3. Просмотр таблицы в Supabase Dashboard или через `npx prisma studio`.

### 4.3. Результаты

При успешной проверке:
- сайт отвечает 200 на главной;
- заявки сохраняются;
- админка доступна только авторизованным.

## 6. Сообщения системному программисту

| Сообщение / ситуация | Содержание | Действия |
|----------------------|------------|----------|
| `Error: P1001` (Prisma) | Не удаётся подключиться к БД | Проверить `DATABASE_URL`, доступность Supabase, SSL |
| `Invalid environment variables` | Отсутствуют переменные | Заполнить `.env` по образцу `.env.example` |
| `Module not found` | Не установлены зависимости | Выполнить `npm install` |
| `401` на /admin | Неверный логин/пароль | Проверить `ADMIN_USER` / `ADMIN_PASS` |
| Ошибка при `prisma generate` | Несовместимость версий | Обновить Prisma, очистить `node_modules` и переустановить |
| Порт 3000 занят | Address already in use | Остановить другой процесс или запустить на другом порту (`-p 3001`) |
| Build failed | Ошибки TypeScript / импортов | Исправить указанные в логе файлы и строки |

### 6.1. Действия при аварийных ситуациях

1. Просмотреть логи сервера (терминал / dashboard хостинга).  
2. Проверить переменные окружения.  
3. При проблемах с БД — проверить статус Supabase и строку подключения.  
4. Перезапустить приложение после исправления.  
5. При необходимости сбросить миграции / заново применить `prisma db push`.
